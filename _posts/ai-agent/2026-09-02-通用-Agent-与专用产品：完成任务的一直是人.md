介绍 photo agent 时，我大概率会被问一个问题：这个产品和 Hermes、OpenClaw 这类通用 agent 应用比，差异在哪里？把照片直接喂给通用 agent，它同样能分析图片、给出摄影指导，专用产品的立足点在哪？

我当时想到的回答思路是，先做一个主语上的转换，再去谈差异。

转换：“AI 能做PPT” -> “我能使用 AI 做一个 PPT”

这篇把它整理成文字，按三层展开，每层都能找到对应的专业说法。

## 第一层：完成任务的从来是人，不是工具

先不要顺着「Hermes 能做到什么」去比功能清单。我目前的看法是，真正完成某件事的主体一直是人。是我有能力把照片放进 Hermes，我有能力组织出合适的提问，我有能力判断回答的好坏，我继续迭代追问，任务才算完成。工具是被牵连进来的。

这个视角不是我的发明，几个领域都有现成概念：

- **分布式认知（Distributed Cognition，Edwin Hutchins）**：认知不只发生在单个脑袋里，而是分布在「人 + 工具 + 环境」的整个系统里。既然成绩算在整个系统头上，评价一个工具就不能只看它孤立状态下的能力上限。说人话就是不能只评价人的能力或者锤子的功能，而是评价拿着一把锤子的人能做到什么事情。
- **延展心智（The Extended Mind，Clark & Chalmers）**：工具是认知的延伸，人和工具构成一个整体。「Hermes 能做到」和「人借助 Hermes 做到」是两个命题，后者才对应真实世界里发生的事。
- **实用性 vs 可用性（Utility vs Usability，Jakob Nielsen）**：实用性问「它能不能做这件事」，可用性问「目标用户能不能在可接受的成本内让它做到」。通用 agent 的实用性接近无穷，但对特定人群的可用性很低。Nielsen 的原式是两者相加（usefulness = usability + utility），我倾向于把产品价值理解成两者的乘积，任何一项趋近于零，乘积就趋近于零。

做完这层转换，问题就从「通用 agent 能不能做」变成了「目标用户能不能借通用 agent 做到」。后一个问题的答案，对大多数人来说是否定的。

## 第二层：通用性的代价，是把负担转嫁给用户

通用 agent 不是能力不够，是通用本身有代价。它把「将模糊需求翻译成一串好提问」的工作，从产品侧转嫁到了用户侧。这些概念可以描述这个代价：

- **空白画布问题（blank page / cold start）**：面对空空的输入框，用户不知道从何说起。可能性越多，越难迈出第一步。
- **选择悖论（Paradox of Choice，Barry Schwartz）**：选项过多反而导致决策瘫痪和放弃（经典的果酱实验出自 Iyengar 与 Lepper，Schwartz 在书里引用并传播了它）。通用 agent 的能力空间是接近无穷的选项集，「不知道从何入手」可以看作这个效应的极端形态。
- **执行鸿沟与评估鸿沟（Gulf of Execution / Gulf of Evaluation，Don Norman《设计心理学》）**：执行鸿沟是「我想做什么」和「我知道怎么让系统做」之间的落差；评估鸿沟是「系统给了我结果」和「我知道这个结果好不好」之间的落差。空对话框只提供了「输入文字」这一个动作，没有告诉用户能问什么、从哪问起，两条鸿沟都留给了用户。摄影新手拿到一段通用 agent 的回答，既不知道还能追问什么，也不知道建议本身靠不靠谱。
- **认知负荷理论（Cognitive Load Theory，John Sweller）**：「琢磨怎么用工具」这部分算外在负荷，它挤占的是用户本来该花在「照片怎么改」上的认知资源。
- **提示词素养（prompt literacy）与终端用户编程（end-user programming）**：对话框是新的命令行。自然语言界面降低的是语法门槛，没有降低方法论门槛：怎么拆解任务、按什么顺序问、怎么验证回答，这套方法论跟编程一样需要学习。「会说话」和「会提问」是两种能力，中间隔着一层素养。
- **情境行动（Situated Action，Lucy Suchman）**：真实用户不是带着完整计划来的，目标是在交互过程中逐步成形的。通用 agent 的交互假设用户一开始就能说清任务，而多数用户的需求是含混的、待引导的，属于**潜在需求（latent needs）**，用户自己都说不清要什么。
- **福格行为模型（B=MAP，BJ Fogg）**：行为发生需要动机（Motivation）、能力（Ability）、触发（Prompt）三者同时到位。通用 agent 对大众用户经常缺两样：能力（不会用）和触发（没有场景提醒他此刻可以用）。我觉得这个模型把我说的「不懂得用」和「不主动用」对得很齐，专用产品补的恰好是 A 和 P：用界面把能力门槛降下来，用场景把触发嵌进去。

## 第三层：专用产品的意义，是把专家的提问方法编码进交互

顺着前两层，photo agent 在做的事可以一句话说清：把「一个会用 AI 的摄影行家会怎么提问、怎么追问」这套方法，固化成交互路径，让用户跟着走，就能得到原本靠自己提问拿不到的输出。对应的概念：

- **脚手架（Scaffolding，Bruner 等人，思想上与 Vygotsky 相通）**：教育心理学里指给初学者搭临时支撑，让他完成原本完成不了的任务，并在过程中逐步内化方法。专用 agent 可以理解为「AI 使用的脚手架」。相关的**最近发展区（Zone of Proximal Development）**指「独自做不到、但在引导下能做到」的区间，产品针对的正是这个区间。
- **可供性与意符（Affordance / Signifier，Norman，affordance 一词借自 Gibson）**：界面上的每个按钮、每个选项，都是在替用户把问题预先问好。按钮是一个成形的问题，选项的分叉是行家才知道的追问方向。空对话框缺的正是这些意符。
- **有主见的软件（Opinionated Software，37signals / Rails 的 convention over configuration）**：替用户做掉方法层面的决策。产品敢规定「先看构图、再谈用光」，用户就不用自己发明一套分析流程。
- **渐进式披露（Progressive Disclosure）与向导式交互（Wizard）**：把复杂任务切成有顺序的步骤，选项随用户的就绪程度逐步展开。
- **约束即功能**：把行动空间收窄，出错空间跟着收窄。agent 设计里对应的说法是行动空间（action space）设计。
- **Prompt 内置于产品**：界面上的一次次点选，最终编译成一条结构化的 prompt。相当于把 prompt engineering 从用户侧搬到产品侧，用户为结果操心，不为措辞劳动。
- **JTBD（Jobs to be Done，Christensen / Ulwick）**：用户「雇用」产品来完成生活中的任务。判断竞品的正确问法不是「别的工具理论上能不能做这件事」，而是「在这个具体场景里，用户会雇谁」。通用 agent 是一个什么都会、但没有场景感的候选人。
- **完整产品（Whole Product，Geoffrey Moore《跨越鸿沟》）**：通用模型只是组件，完整产品要在组件外面包上工作流、引导和信任，大众用户买的从来是完整产品。
- **应用层价值**：模型能力不等于产品价值，应用层的价值在拥有工作流，不在拥有模型。行业里「wrapper 之争」的回应也在这里：会被通用 agent 替代的是没把方法和场景编进产品的 wrapper。

## 压成 30 秒怎么说

把上面的内容压成一段可以直接说出口的话：

「我先把这个问题的主语换一下。完成任务的一直是人，不是工具。Hermes 显得什么都能做，是因为驱动它的人会提问、会拆任务、会判断回答的好坏。把这套能力拿掉，只把照片丢给它，多数人得到的只是一段泛泛的点评。所以我觉得差异不在能力，在可用性：通用 agent 把最难的部分留给了用户，不知道从何问起，不知道怎么追问，也没有场景提醒他此刻能用上。photo agent 做的事，是把一个会用 AI 的摄影行家的提问方法，固化成一条交互路径，用户跟着界面走，就能拿到自己提问拿不到的输出。我们和通用 agent 服务的与其说是两群人，不如说是同一个人的两种状态。」

## 这个说法的边界

主动说出边界，比等别人追问要稳：

- 会提问的头部用户，用通用 agent 确实就够了。专用产品要把方法、数据、交互都做进去才立得住，只包一层对话就是真的 wrapper。
- 通用 agent 自己也在进化，proactivity 和记忆能力上来之后，「触发」和「不知道从何入手」这两点会被部分缓解。所以护城河要落在方法和数据的沉淀上，不能只落在交互形式上。
- 数据侧也有差异（本地照片的批量接入、组织、隐私），通用 agent 处理起来目前并不顺，不过这不是我这段思考的重点，先记一笔。
