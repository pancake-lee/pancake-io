上一篇《结构化思维工具箱》整理了知识地图、默认流程和卡壳速查表。工具这种东西，光看地图记不住，得拿一个真实问题练一遍才有感觉。

练习题是找 Hermes 要的。那天晚上我在手机上，让它「考考我关键的，然后我回答后你补充更多扩展信息」，它出了这道题：

**AI 应用层的一个核心矛盾是 "能力越来越强，但可控性越来越差"。用金字塔原理拆解：**

1. **结论先行**：如果让你用一句话总结这个矛盾的应对策略，是什么？
2. **以上统下**：这个策略需要哪 3 个支撑维度？（提示：可以从人、流程、技术角度想）
3. **MECE 检查**：这 3 个维度有没有重叠？有没有漏掉关键角度？

接下来三版答案，回答的都是这道题，尤其是加粗的那句核心矛盾。每一版的毛病、被批改的过程和修法都记在下面，最后沉淀出两个很实用的知识点：金字塔原理的三种原生分类，以及「结构顺序必须同一抽象度」这个陷阱。

PS: 当前 AI 的发展速度太快，上面说的“可控性越来越差”仅限于我自己某一段时间体会到的，某些模型升级后反而“想太多”的情况，并不是普遍现象。但本文的核心是我如何去思考这个问题，而并不深究问题本身。

## 一、初次回答：按时间线叙述，不是分类

**结论**：AI 发展 = 人类组织发展模式，两个方向并行。

**分层**：

```
├─ 一、问题根源：期望错配
│   └─ 用户用"一句话"提需求，但不知道自己要什么
│   └─ AI 越强，输出越复杂，细节错误越刺眼 → 被认为不可靠
│
├─ 二、演进路径：从个体到组织
│   └─ 在校生（简单工具）→ 工程师（单 Agent）→ 团队（多 Agent 协作）
│   └─ 规模扩大 → 沟通成本上升（与人类组织同构）
│
└─ 三、未来方向：两个并行
    ├─ 更强个体：超级 Agent，单兵作战
    └─ 协作组织：流程 + 多 Agent，用系统消除个体错误
```

**问题诊断**：

| 问题               | 说明                                                 |
| ------------------ | ---------------------------------------------------- |
| 分层逻辑是"时间线" | 按过去→现在→未来叙述，不是静态分类                   |
| 缺了"人和AI交互"   | 只有人、只有AI，没有两者之间的关系                   |
| 结论是"描述现象"   | 没有回答"怎么解"，只是说了"是什么"                   |
| 抽象度不一致       | "问题根源"是原因，"演进路径"是过程，"未来方向"是预测 |

## 二、二次回答：补上交互，但抽象度还是乱

**结论**：把 AI 当人/团队管，用已知的人类管理方法解决 AI 协作问题。

**分层**（结构顺序：人 / AI / 交互）：

```
├─ 人
│   └─ 期望错配
│
├─ AI
│   ├─ 单体：超级个体
│   │   ├─ 模型能力
│   │   ├─ agent内流程编排
│   │   ├─ rag
│   │   ├─ tools（cli / mcp）
│   │   └─ context（skill / prompt / history / memory）
│   │
│   └─ 协作
│       ├─ 形式上：岗位、开发流程、会议
│       └─ 技术上：agent之间的交互
│
└─ 人和AI交互
    ├─ 交互方式：多模态输入
    └─ 交互流程：AI主动追问，而非单次循环
```

**问题诊断**：

| 问题                   | 说明                                                   |
| ---------------------- | ------------------------------------------------------ |
| 结构顺序的抽象度不一致 | "人"是角色，"AI"是系统，"交互"是过程，三者不是同类     |
| "协作"层混了维度       | "岗位"按角色分，"流程"按时间分，"技术交互"按通信方式分 |
| "人"层太薄             | 只有"期望错配"一个点，缺角色、能力、信任等             |
| 仍缺"环境约束"         | 算力、数据、安全、合规，不是管理对象，但制约全部       |

## 三、更好的回答：2W1H + 结构顺序混用

**结论**（同二次回答）：把 AI 当人/团队管，用已知的人类管理方法解决 AI 协作问题。

**第一层：2W1H（逻辑顺序）**：

```
├─ 为什么能这么干？
│   └─ AI演进复刻了人类组织演进（个体→团队→公司）
│   └─ 人类已有的管理工具（敏捷、评审、复盘）可直接迁移
│
├─ 管的对象是什么？（结构顺序）
│   ├─ 参与者：人（角色、能力、期望、信任）
│   ├─ 工具：AI单体（模型、编排、RAG、工具、上下文）
│   ├─ 组织：AI协作（岗位、流程、技术通信）
│   └─ 界面：人和AI交互（多模态、主动追问、反馈循环）
│
└─ 具体怎么管？
    ├─ 管个体 = 给工具、给上下文、给明确目标
    ├─ 管协作 = 分岗位、定流程、开例会
    ├─ 管交互 = 设计多模态输入 + AI主动澄清机制
    └─ 管期望 = 让用户理解"AI会犯错，像人一样需要迭代"
```

**关键修正点**：

| 修正                 | 说明                                         |
| -------------------- | -------------------------------------------- |
| 第一层用2W1H         | 按"问题类型"分，不依赖具体事物的结构         |
| 第二层才用结构顺序   | "管的对象"下四人组都是"东西"，抽象度一致     |
| "交互"降级为"界面"   | 不是独立一级，而是对象之一                   |
| 补了"管期望"         | 回应原始问题的核心矛盾                       |
| 补了"环境约束"的说明 | 在结论中限定范围：聚焦组织行为，基础设施另议 |

## 四、沉淀出的知识点

### 金字塔原理的 3 种原生分类（芭芭拉·明托）

| 分类         | 适用场景         | 例子                                  |
| ------------ | ---------------- | ------------------------------------- |
| **时间顺序** | 步骤、流程、阶段 | 第一、第二、第三；计划→开发→测试→发布 |
| **结构顺序** | 组成、空间、部门 | 北京/上海/广州；硬件/软件/服务        |
| **程度顺序** | 重要性、优先级   | 最重要、次重要；核心问题、衍生问题    |

### 2W1H（逻辑顺序）

不是明托原生分类，是通用思维框架，常与原生分类混用：

| 层级                   | 用途                                 |
| ---------------------- | ------------------------------------ |
| 第一层用2W1H           | 确定分析角度（为什么/是什么/怎么做） |
| 第二层用结构/时间/程度 | 在确定的角度下，对具体事物分类       |

### 结构顺序的陷阱

**必须满足：同一层级、同一抽象度。**

错误示例：

- ❌ 人（角色）/ AI（系统）/ 交互（过程）
- ❌ 岗位（角色）/ 开发流程（时间）/ 技术交互（通信方式）

正确示例：

- ✅ 参与者 / 工具 / 组织 / 界面（都是「东西」）
- ✅ 计划 / 开发 / 测试 / 发布（都是「阶段」）

## 五、自检清单

拆解完成后，逐条检查：

- 结论是否回答了原始问题？
- 第一层用的是哪种顺序？是否合适？
- 每一层内部是否同一抽象度？
- 是否 MECE（互斥且穷尽）？
- 有没有把「关系」错当成「组成部分」？
- 有没有遗漏的约束条件（环境、资源、时间）？

这套清单我现在还在用，每次拆完扫一遍，十有八九能扫出一点毛病。
